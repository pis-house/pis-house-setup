# Pis House Setup Tool ドキュメント

本ドキュメントは、スマートホーム設定ツール `pis-house-setup` に関する情報を、「利用者向け」と「開発者向け」に分けて記述したものです。

---

## 🟢 1. 利用者向けガイド (User Guide)

このセクションでは、居住者やシステム利用者が知っておくべき「このツールで何ができるか」「利用上の注意」について説明します。

### 1.1 システムの概要（これって何？）
**Pis House Setup Tool** は、スマートホーム（Pis House）で使用する IoT デバイス（赤外線コントローラー）を、すぐに使える状態にするための設定ツールです。

買ってきたばかりのマイコン（ESP32）に Wi-Fi 設定を書き込んだり、エアコンや照明のリモコン信号を学習させたりして、スマホアプリから操作できるように準備します。

### 1.2 主な機能（何ができるの？）

このツールを使うことで、以下の設定作業を行えます。

1.  **デバイスの初期セットアップ（Wi-Fi設定）**
    * PC に USB 接続したデバイスに対して、家庭内の Wi-Fi 情報（SSID やパスワード）を書き込みます。
    * PC が接続しているネットワーク情報を読み取って、デバイス用の IP アドレスを自動で割り当てる機能があるため、難しい設定を意識せずにセットアップできます。
2.  **赤外線リモコン信号の登録**
    * エアコンや照明を操作するための「赤外線信号」をデバイスに登録します。
    * 「冷房」「暖房」「電源ON/OFF」などの操作ごとに信号を設定でき、主要メーカーの形式に対応しています。
3.  **スマホアプリとの連携（ID発行）**
    * 設定したデバイスをスマホアプリ（Pis House App）から操作するための「連携用ID」を発行・表示します。

### 1.3 利用の流れ

1.  **接続**: 設定したい ESP32 を PC の USB ポートに接続します。
2.  **新規作成**: ツール上で「新規」を選び、デバイス名や Wi-Fi 情報を入力して「設定」ボタンを押します。（これでデバイスに設定が書き込まれます）
3.  **赤外線登録**: 作成したデバイスを選び、「赤外線登録」から家電のリモコン信号を設定します。
4.  **アプリ連携**: 「システム情報」画面にある ID を確認し、自分のスマホアプリに入力します。

### 1.4 利用上の注意

* **設定中はケーブルを抜かない**
    * 「設定」ボタンを押して書き込み処理が行われている間は、絶対に USB ケーブルを抜かないでください。故障の原因となります。
* **家電の操作について**
    * このツールはあくまで「設定用」です。日々の家電操作（エアコンをつける、電気を消す等）は、連携設定を行った後のスマホアプリから行ってください。

## 🔵 2. 開発者向けドキュメント (Developer Documentation)

このセクションでは、エンジニアや保守担当者向けに、システムのアーキテクチャ、技術スタック、モジュール構成について詳述します。

### 2.1 システムスペック

| 項目 | 内容 |
| :--- | :--- |
| **システム名** | pis-house-setup |
| **プラットフォーム** | Linux (Raspberry Pi OS 推奨) |
| **言語/GUI** | Python 3.x / Tkinter |
| **外部ツール** | `esptool.py` (書き込み), `mklittlefs` (イメージ作成) |
| **クラウドDB** | Firebase Firestore |

### 2.2 システムの目的と範囲

本システムは、**IoTデバイス（ESP32）のプロビジョニング（初期キッティング）**を行うための専用ツールです。

* **担当範囲 (In-Scope)**:
    * **GUI入力**: デバイス名、Wi-Fi情報、赤外線データの入力インターフェース提供。
    * **物理書き込み**: ESP32 のフラッシュメモリへの設定ファイル（LittleFSイメージ）焼き込み。
    * **クラウド登録**: Firestore へのデバイスメタデータおよび赤外線コードの登録。
    * **UUID生成**: アプリ連携用のユニークID（`app_uuid.txt`）の生成と管理。
* **範囲外 (Out-of-Scope)**:
    * **デバイス制御**: 稼働中のデバイスに対する操作（これは `pis-house-control-server` の役割）。
    * **ファームウェアビルド**: Arduino/PlatformIO 等によるバイナリのコンパイル自体は行わない（事前に焼かれている前提で、設定領域のみを上書きする）。

### 2.3 アーキテクチャ設計

本システムは、GUI（Tkinter）からの入力をトリガーに、**「物理デバイスへのシリアル通信」**と**「クラウドデータベースへのAPI通信」**を並行して行います。
